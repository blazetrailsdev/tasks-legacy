## Context

`packages/activerecord/src/enum.ts:990` reads the schema memo raw:

```ts
const column = host._columnsHash?.[name];
```

`blazetrails/schema-memo-read-through-guard` rejects exactly this — JS statics
are inherited where Ruby class ivars are not, so on a subclass a raw
`_columnsHash` read serves the ANCESTOR's memo, which is stale the moment an
ancestor stamps `_schemaRevision`. `pnpm lint` reports it as an error in a
worktree whose `eslint/*.json` manifests have just been regenerated by
`pnpm parity:api`; those manifests are gitignored, so the error does not
necessarily surface in a stale-manifest checkout.

Landed in 3420c6117 ("fix(parity): ... enum schema reentrancy", #6703).
Observed while running the pre-PR gates for #6710, which touched neither file.

## Converged shape

Read it through `ownSchemaMemo(host, "_columnsHash")` (or `isSchemaLoaded`),
which applies the `schemaStaleAgainstAncestors` pull fallback — the remedy the
rule's own message names. Confirm the STI subclass case: an enum whose backing
column is declared on the base should still resolve from the subclass after the
base stamps a revision.
